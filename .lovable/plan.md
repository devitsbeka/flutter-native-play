

# Fix: Guest Players Can't Play After Poll

## Problem Summary

After a poll ends and a new round starts, guest players (who joined via QR code) cannot answer questions. Only the host can interact with the game. The questions advance automatically because the system expects answers from all 3 players but receives 0.

## Root Cause Analysis

Based on deep investigation of the database, console logs, and network requests:

### Evidence Found

1. **Database shows all 3 players are `is_active: true`** - The RLS UPDATE policy fix is working
2. **All 3 players have answers recorded for questions 0-4** (first round) - First round works
3. **Question 5 shows `actualAnswers: 0, expectedPlayers: 3`** - No one can answer after poll
4. **No network requests from guest devices for answer inserts** - Guests aren't even trying to submit
5. **Guest players have `user_id: NULL`** in `tv_players` table - The `user_id` sync is still failing

### The Critical Bug

The `user_id` sync in `finalizePollAndStartGame` is checking if `player_id` is a UUID to decide whether to sync `user_id`. But for QR code guests, their `player_id` IS a valid UUID (generated by `crypto.randomUUID()` on their device), so the code tries to set `user_id = player_id`. **However, this update is still being blocked by something, leaving `user_id: NULL`**.

Looking at the RLS policy for `tv_players` UPDATE:
```sql
EXISTS (SELECT 1 FROM tv_sessions ts 
        WHERE ts.id = tv_players.tv_session_id 
        AND ts.host_user_id = auth.uid())
```

This should allow the host to update guest records. But wait - the `user_id` sync loop is trying to set `user_id: player_id` where `player_id` is a random UUID that's not an actual auth user. This might be causing silent failures or unexpected behavior.

**The actual root cause**: When the poll finishes, the `finalizePollAndStartGame` function on the host's device:
1. Sets `current_round_suggester_id` to the winning suggestion's `user_id`
2. This `user_id` might be the host's ID if the host suggested the category
3. Then in `ControllerQuestion`, ALL players including guests check: `isSuggester = myPlayerId === currentRoundSuggesterId`
4. If `currentRoundSuggesterId` is not properly synced to guest devices, or if there's stale state, guests might be incorrectly blocked

But actually, looking more carefully - the network logs show no answer requests from guests. This means they're not even trying to click. This points to either:
- `questions.length === 0` showing the error screen
- The `isSuggester` check incorrectly blocking them
- Some other UI blocking issue

## The Fix

The issue is multi-layered. We need to ensure:

### Fix 1: Force `player_answers` DELETE before new round

The `finalizePollAndStartGame` does delete old answers, but when transitioning from `poll-results` to `countdown`, there might be a race condition where old answers aren't fully cleared before the new round's answer count check runs.

**File:** `src/hooks/useTVPoll.ts`

Add a longer delay after deleting old answers and before updating the session status:

```typescript
// Clear any old player answers for this session
const { error: deleteError } = await supabase
  .from('player_answers')
  .delete()
  .eq('tv_session_id', sessionId);

if (deleteError) {
  console.error('[finalizePollAndStartGame] ⚠️ Failed to delete old answers:', deleteError);
}

// CRITICAL: Wait for delete to propagate
await new Promise(resolve => setTimeout(resolve, 300));
```

### Fix 2: Ensure Guest `myPlayerId` is correctly preserved

When guests refresh or the page re-renders during poll transition, their `myPlayerId` might be regenerated or lost.

**File:** `src/contexts/TVGameContext.tsx`

In the session subscription handler, ensure we don't lose the `myPlayerId` during phase transitions:

```typescript
// At the top of the subscription handler, preserve critical identities
const currentMyPlayerId = myPlayerId; // Capture at start of handler
```

### Fix 3: Clear suggester ID between rounds

When a poll ends and a new round starts, the `current_round_suggester_id` should be explicitly set. Currently it might retain stale data.

**File:** `src/hooks/useTVPoll.ts`

Already implemented in previous changes - verify it's working correctly.

```typescript
}
```

### Fix 6: Verify RLS is not blocking answer inserts for guests

The `player_answers` INSERT policy has:
```sql
(tv_session_id IS NOT NULL) AND (EXISTS (SELECT 1 FROM tv_sessions ts 
  WHERE ts.id = player_answers.tv_session_id 
  AND ts.status = ANY ('playing', 'question', 'reveal')))
```

This should allow guests to insert. But the code uses `user_id: myPlayerId` which for guests is a random UUID. The RLS check for `auth.uid() = user_id` will fail because `auth.uid()` is NULL for guests.

**However**, the second OR condition should still pass. Let me verify the code is correctly including `tv_session_id` in the insert.

Looking at `submitAnswer` (line 1980-1988):
```typescript
const { error } = await supabase.from('player_answers').insert({
  tv_session_id: state.sessionId,  // ✓ Present
  room_id: roomIdToUse,
  user_id: myPlayerId,
  question_index: state.currentQuestionIndex,
  answer,
  is_correct: isCorrect,
  points_earned: points,
  time_remaining: state.timeRemaining,
});
```

This should work with the RLS policy. The issue must be earlier - guests aren't even calling `submitAnswer`.
